### Продуктовые материалы — три компактных документа

Организатор указал, что не требуется готовить все возможные документы. Мы сдаём три, покрывающие требуемый состав:

1. **`02-produktovoe-videnie.md`** — кто пользователь и какую проблему решаем, продуктовая гипотеза, ценностное предложение, границы MVP, основной сценарий, предварительные критерии успеха, риски.
2. **`03-zhurnal-dopushcheniy.md`** — одиннадцать развилок по методике организатора: цель → как неопределённость влияет на решение → что нужно, чтобы решить → как снизить → прокси → что делаем, если решать нужно сейчас.
3. **`04-ai-product-i-tehnicheskaya-svyaz.md`** — вклад AI Product и связь каждого продуктового решения с конкретным изменением в коде.

| Компонент | Статус | Срок |

| Правило комбинирования и добор до полосы частоты | не начато. Полоса измеряется (`run_product_numbers.py`), но ни одно правило в неё не попадает — добор нужен именно поэтому | 05.09 |
| Настоящий процентиль в тексте пуша | библиотека текстов опирается на него (`{процент}`/`{редкость}`), но правило рендера с нижним порогом отправки не написано | 06.09 |
| Переотбор признаков внутри каждого фолда | сейчас конфигурация фиксируется один раз на данных до 2021 — консервативно, но расходится с продакшн-сценарием | 07.09 |

| Прототип экрана «момент изменился» | готов: экран «открыт позже» в макете (`figures/06`, экран 05) и разбор сроков в `13-ustarevanie-signala.md` | завершено |

| Значимость на клиентской метрике | ни одна политика её не даёт: у лучшей — ценности действия — ДИ [−71; +401] на 53 окнах. Больше данных из ЦБ взять неоткуда, поэтому проверять придётся пилотом | пилот |

## Как проверить наши результаты

```bash
git clone https://github.com/tarma3v/international_transfers_signals
cd international_transfers_signals
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

.venv/bin/python -m ml.leakage             # ворота: доказательство отсутствия утечки
.venv/bin/python -m pytest -c pytest.ini   # 49 тестов: честность, корректность, срез
.venv/bin/python -m ml.signals             # сигналы на произвольную дату среза
.venv/bin/python run_product_numbers.py    # все продуктовые величины из документов
.venv/bin/python run_experiment.py         # базовые модели против индикаторов ТЗ
.venv/bin/python run_boosting.py           # CatBoost, XGBoost + отбор признаков
.venv/bin/python run_two_models.py         # две модели под две метрики
.venv/bin/python run_signal_staleness.py   # устаревание сигнала: сроки жизни пуша
```

XGBoost на macOS требует OpenMP: `brew install libomp`.

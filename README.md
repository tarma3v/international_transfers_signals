# Сигналы для международных переводов

Исследовательский прототип для кейса Альфа-Банка: определить, когда клиенту
выгоднее переводить рубли в **AMD, KGS, KZT, TJS или UZS**, и сформировать не
больше нескольких полезных сигналов в неделю.

> **Текущий исследовательский ориентир:** причинный `availability_route` на
> срезе 15:30. На ретроспективе 2025–2026 он даёт adjusted lift **2,053** при
> `h=5` и около **1,19 сигнала на валюту в неделю**. Добавление прямых биржевых
> пар каждой валюты подтверждённого улучшения не дало, поэтому основная модель
> не заменена.

[Краткая история всех экспериментов](EXPERIMENTS_SUMMARY.md) ·
[текущее решение подробно](docs/05-tekushchee-reshenie.md) ·
[последний PDF](output/pdf/ivan_direct_pairs_and_widget_report.pdf)

## Что предсказываем

В данных находится официальный курс Банка России: сколько рублей стоит единица
валюты получателя с учётом номинала. Чем ниже этот курс, тем выгоднее перевод.

Для даты `t` и горизонта `h` положительная цель означает:

```text
rate(t) <= min(rate(t+1), ..., rate(t+h))
```

Иными словами, сигнал «перевести сейчас» считается удачным, если в следующих
`h` публикациях ЦБ более дешёвого курса не появилось. В scorecard одновременно
используются `h = 1, 3, 5, 10, 20`; `h=5` служит удобной внутренней точкой
сравнения, но не заменяет остальные горизонты.

Основная метрика — **lift**:

```text
доля удачных дней среди сигналов / доля удачных дней среди всех допустимых дней
```

Также считаются частота, результат по каждой валюте и году, официальная выгода
в симметричном окне `-h..+h` и более строгая future-only выгода.

## Текущий результат

| Показатель | Значение |
|---|---:|
| adjusted lift, `h=1/3/5/10/20` | 1,780 / 2,014 / **2,053** / 2,005 / 1,928 |
| pooled lift, `h=5` | 2,059 |
| точность сигналов, `h=5` | 279 / 506 = 55,14% |
| базовая доля удачных дней | 26,78% |
| частота | 1,19 сигнала на валюту в неделю |
| оценочный период `h=5` | 10.01.2025–26.08.2026, 2020 строк валюта-дата |

Это **причинный ретроспективный backtest**, а не результат свежего закрытого
теста: период 2025–2026 уже много раз изучался. Число годится как текущий
инженерный ориентир и кандидат для prospective shadow, но не как несмещённая
оценка будущего продакшена.

## Как работает модель 15:30

1. Для CNY/RUB берутся только завершённые десятиминутные свечи MOEX из окна
   10:00–15:30 по Москве.
2. Считается геометрическое среднее цен и его signed basis относительно
   последнего доступного на этот момент курса CNY Банка России.
3. Basis переводится в причинный ранг относительно последних 250 доступных
   наблюдений. Будущие даты в ранге отсутствуют.
4. Если текущей CNY-сессии нет, роутер использует заранее определённый noon
   fallback, а строка не удаляется из оценки.
5. Пуш получают верхние 22% значений относительно предыдущих 20 оценок.

Юань здесь выступает как ликвидный внутридневной индикатор общего движения
рубля. Валюта назначения и её история всё равно присутствуют в панели; один и
тот же CNY-сигнал преобразуется в решение отдельно для каждого коридора.

Модель не использует неопубликованный курс ЦБ на завтра. Отдельный сценарий
после фактической публикации следующего курса существует в исследовании, но не
смешивается с основной моделью.

## Что дали прямые пары каждой валюты

В round 7 собраны **99 013** десятиминутных CETS-свечей TOM/TOD для всех пяти
валют. Проверены 43 варианта прямых basis/классификаторов и ещё 20 моделей
остатка относительно CNY anchor.

| Зафиксированный вариант | adjusted lift `h=5` |
|---|---:|
| текущий CNY availability-router | **2,053** |
| общая мягкая добавка прямой пары 25% | 2,043 |
| CNY anchor + quantile residual 10% | 2,038 |
| веса, подобранные отдельно по валютам | 1,978 |

Индивидуальные веса, зафиксированные на purged 2024: KZT 75%, AMD 25%, KGS
50%, TJS 0%, UZS 50%. На 2025–2026 они перенеслись хуже базы; средняя разница
по горизонтам `-0,092`, paired 95% CI `[-0,154; -0,030]`. Это не «лучшие веса
на будущее», а честно сохранённый отрицательный результат.

Причина ожидаема по данным: KZT и AMD торгуются достаточно плотно, KGS и UZS
разрежены, а для TJS в CETS нет пригодных наблюдений 2025–2026. Большой локальный
вес поэтому добавляет шум и нестабильный basis. Невыбранные варианты с красивой
цифрой на уже открытом периоде не объявляются новым результатом.

## Индикатор полезности перевода

Для виджета сырой ранг модели нельзя показывать как вероятность. Поверх
замороженного score обучается квартальный логистический калибратор только на
уже разрешившихся прошлых исходах. На ретроспективном срезе 15:30:

| Прогноз | Brier score, меньше лучше |
|---|---:|
| сырой ранг, ошибочно прочитанный как вероятность | 0,224 |
| постоянная вероятность из train | 0,200 |
| квартально откалиброванная вероятность | **0,155** |

Интерфейс может показывать непрерывный score 0–100, вероятность удачного момента,
время котировки и признак свежести. Однако сейчас валидирован только срез 15:30.
Для настоящего intraday-виджета нужны отдельные исторические срезы 10:30, 12:00,
14:00, 15:30 и 17:00 и разбиение по дням. Экономию в рублях можно оценивать
только после добавления исполнимого банковского курса, комиссий и лимитов.

## Честность и защита от утечек

- признаки строятся только из временного среза прошлого;
- train очищается по фактической дате разрешения target, а не фиксированным
  числом календарных дней;
- рабочая точка и выбор модели фиксируются на прошлом периоде;
- отсутствующие рыночные дни остаются в знаменателе;
- признаки проходят corruption-тесты: изменение будущих цен и исходов не может
  изменить ранние оценки;
- свежий сигнал сравнивается с matched stale-контролем;
- интервалы считаются парным bootstrap по четырёхнедельным блокам;
- 2025–2026 всегда помечается как уже исследованная ретроспектива.

Политика описана в [`research/case_qa_20260905_notes.md`](research/case_qa_20260905_notes.md),
текущий протокол — в [`research/round7_protocol.md`](research/round7_protocol.md).

## Быстрый старт

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
PYTHONPATH=. .venv/bin/pytest -q

# Воспроизвести последний локальный раунд на сохранённых данных
PYTHONPATH=. .venv/bin/python -m research.round7_direct_pairs
PYTHONPATH=. .venv/bin/python -m research.round7_residual_floor
PYTHONPATH=. .venv/bin/python -m research.round7_audit
PYTHONPATH=. .venv/bin/python -m research.build_round7_report
```

Полный набор содержит **112 тестов**. Повторная загрузка данных MOEX требует
сети: `PYTHONPATH=. .venv/bin/python -m research.round7_direct_pairs_data`.
XGBoost на macOS может потребовать `brew install libomp`.
